# 구독 서버의 계정과 자료 경계

구독 서비스의 구현 기반을 준비하는 문서다. 현재 배포 데이터의 상업용 권리 검토가 통과하지 않아 실제 hosted 서버 시작은 차단된다. 결제·실제 고객 계정·외부 배포는 실행하지 않았다. [권리 등록부](rights-register-2026-09-07.md), [회사 이용허락 초안](company-license-draft.ko.md)과 함께 검토한다.

## 선택한 구조

기존 React/FastAPI/SQLModel/SQLite를 유지한다. 기본 `HOSTED_MODE=false`에서는 원래 데스크톱의 DB와 로그인 없는 사용을 유지한다. 구독 계정은 별도 모드이며 소스 디렉터리 밖에 지정한 비공개 위치에 저장한다.

| 범위 | 저장 내용 | 요청 권한 |
|---|---|---|
| 회사 | 회사 식별자·표시명, 계약 상태·기간·좌석 수 | 운영자가 확인된 계약에 따라 기록; 신규 회사는 대기 상태 |
| 계정 | 회사 소속, 로그인 이름, 비밀번호 해시, 활성 상태 | 서버의 로그인 세션으로 결정 |
| 계정별 DB | 저장 계산, 조성·사용자 재료, 설비, 실제 비용 관측, 해당 DB의 시세 | 로그인한 본인의 저장소만 선택; 클라이언트가 저장소/회사 ID를 지정하지 않음 |
| 공통 파일 | 번들 제조법·상수·문헌 카탈로그 | 권리 검토가 통과한 파일만 서비스 시작에 사용 |

보수적인 가정으로 **같은 회사의 다른 계정에도 자료를 자동 공유하지 않는다**. 협업 공유·회사 관리자의 연구 자료 열람은 별도 동의와 권한 설계 없이는 제공하지 않는다. 회사 식별자는 계약 관리용이고, 계산 데이터 격리는 계정별로 더 좁게 적용한다. 운영 시스템 관리자에게서 데이터를 암호학적으로 숨기는 구조는 아니며, 실제 호스트·백업 접근 권한은 별도로 관리해야 한다.

FastAPI의 전역 의존성이 API 인증을 기본 적용한다. 공개 API는 건강 확인, 자신의 세션 상태, 로그인뿐이다. `get_session`은 서버가 확인한 계정의 UUID로 DB를 고른다. 저장소가 없으면503을 반환하며 데스크톱 DB로 대체하지 않는다. 기존 계정 없는 데스크톱 자료를 임의로 회사 계정에 옮기지 않는다. 기존 자료 테이블의 파괴적 변경이나 소유권 추정도 하지 않는다.

## 인증·요청 보호

비밀번호는 Python 표준 라이브러리의 scrypt(N=2¹⁷,r=8,p=1), 무작위 salt와 일정 시간 비교로 검증한다. 이 구성은 Argon2id를 사용할 수 없을 때의 [OWASP 권장 구성](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)을 따른다. 새 의존성이나 독자적인 암호 알고리즘을 추가하지 않는다. 설정된 비밀번호 길이는15–128문자이며 실제 비밀번호를 로그·명령행 인자에 남기지 않는 운영 절차를 사용해야 한다.

HTTPS 세션 쿠키는 `__Host-` 접두사, Secure, HttpOnly, SameSite=Strict와 경로 `/`를 사용하며 Domain을 지정하지 않는다. 브라우저에는 임의 세션 식별자만 있고 DB에는 그 해시와 계정·만료 시각만 있다. 로그인 시 기존 브라우저 세션을 교체하고, 로그아웃/계정 중지 시 서버 세션을 무효화한다. 절대 만료는12시간, 계정별 활성 세션 저장 상한은5개다. 세션이나 비밀번호를 localStorage에 보관하지 않는다.

쓰기·로그인 요청에는 정확히 일치하는 설정 Origin과 `X-Comet-Request: 1` 헤더가 필요하다. 브라우저의 일반 폼 제출로 해당 헤더를 만들 수 없는 [OWASP의 AJAX/API 헤더 방식](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html#employing-custom-request-headers-for-ajaxapi)을 적용하고 Origin을 추가 확인한다. hosted 모드에서 교차 출처 CORS를 열지 않는다. 로그인 오류는 계정 존재 여부를 구분하지 않으며, 잘못된 요청 본문에 포함된 비밀번호도 오류 응답에 되비추지 않는다.

로그인 시도는 SQLite의 원자적 카운터로 분당 계정5회/클라이언트20회/서버60회까지 허용한다. 성공한 시도도 포함한다. 비밀번호 검증은 프로세스당 동시에2개로 제한한다. 전체 요청 본문은 Content-Length 유무와 관계없이 파싱 전에2MiB로 제한한다. 이 수치는 초기 보호 설정이며 실제 고객 부하 시험이나 가용성 보장이 아니다. API 계산 사용량 제한과 운영 용량 검증은 후속 작업이다.

hosted 응답은 캐시 금지, 프레임 차단, nosniff, referrer 제한과 자체 스크립트 출처 제한 CSP를 적용한다. 제조법 식별자는 영문·숫자·밑줄·하이픈만 허용하고, 실제 경로가 카탈로그 안에 있는지 확인한다. 전체 저장소의 침투 시험을 마쳤다는 뜻은 아니다.

## 시작 조건과 운영 한계

`HOSTED_MODE`, `HOSTED_ORIGIN`, `HOSTED_STORAGE_DIR`, `HOSTED_RIGHTS_MANIFEST`가 준비된다. Origin은 하나의 HTTPS 출처여야 하며 `ALLOWED_HOSTS`에 일치하는 호스트를 명시한다. DEBUG는 꺼져 있어야 한다. `HOSTED_ALLOW_LOCAL_HTTP=true`는 localhost/loopback 시험에만 적용되며 별도의 로컬 쿠키 이름을 사용한다. 상업용 권리 확인 자체를 건너뛰는 실행 옵션은 없다. 자동화 테스트에서만 가짜 심사 결과와 임시 저장소를 명시적으로 주입한다.

실제 서버의 TLS 종료, 프록시 신뢰 IP, 외부에서 백엔드 직접 접근 차단, 서비스 전용 OS 계정과 디렉터리 ACL, 디스크/백업 암호화, 복구 절차는 운영 단계에서 확인해야 한다. Windows에서는 Python의 디렉터리 mode 값만으로 ACL을 보장할 수 없다. 멀티 노드 공유 SQLite·인터넷 직접 노출·SSO/MFA·셀프 가입·자동 청구를 구현했다고 주장하지 않는다. 운영자 명령과 구독 만료·좌석·감사 기록은 [운영 절차](hosted-operations.ko.md)에 정리했다. 계정 화면과 복구 검증은 후속 작업이다.

hosted 모드는 외부 시세 수집 스케줄러를 시작하지 않고 수동 새로고침도 거절한다. 다운로드 라이브러리의 라이선스와 데이터의 상업용 재사용 허락은 별개다. 허락이 확인된 무료 데이터나 사용자가 적법하게 입력한 자료만 향후 운영 입력으로 삼는다. 현재의 배포 보류를 해제하거나 유료 데이터 계약을 체결하지 않았다.
