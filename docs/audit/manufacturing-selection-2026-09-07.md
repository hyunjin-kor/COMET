## 재현과 수정

실제 Chrome에서 FCC 제조법(`fcc_catalyst_usy_w_re`, 20 short tons)을 선택했습니다. 기존 화면에서는 9회 반복하는 `reactor_simple`을 해제하면 9회 모두 사라지고, 다시 선택하면 1회만 추가됐습니다. 총 단계는 **25 → 16 → 17**로 바뀌고 선택된 제조법 ID도 `null`이 됐습니다. 선택 표시가 추가되면서 버튼 너비도 **135.672 ↔ 187.484 px**로 달라졌습니다. [수정 전 상태](manufacturing-before-2026-09-07.json)와 [화면](screens/manufacturing-before-2026-09-07.png)을 보존했습니다.

수정 후에는 제조법의 기준 단계 목록과 실제 선택 목록을 따로 보존합니다. 해제한 작업을 다시 선택하면 기준 목록의 반복 횟수와 순서가 복원되고, 나머지 수동 편집은 유지됩니다. 다른 제조법으로 자동 변경하지 않으며, 선택한 제조법을 수정한 경우 결과의 산정 범위에도 편집 사실을 전달합니다. 표준 단계로 돌아가는 동작은 별도의 복원 버튼으로 제공합니다.

규모 변경 중 늦게 도착한 API 응답이 수동 편집을 덮어쓰지 않도록 했습니다. 규모별 대체 장비를 다시 이전 규모로 바꿀 때도 의도적으로 뺀 단계를 유지합니다. 저장·불러오기와 세션 재로딩에서 기준 목록을 복원하고, 모든 단계를 해제한 빈 목록도 그대로 보존합니다.

## 계산 결과와 가정

엔진·공정 단가·가격 데이터·LCA 계수는 바꾸지 않았습니다. 기존 UI가 재선택 시 누락하던 반복 단계를 이제 API에 온전히 전달하므로 **해제 후 재선택한 계산은 이전의 잘못된 결과와 달라질 수 있습니다**. 제조법의 표준 목록을 처음 선택했을 때와 복원했을 때의 계산 결과는 같습니다. 반복 횟수는 제조법의 기존 기준을 사용하며 사용자가 임의 횟수를 입력하는 기능은 추가하지 않았습니다.

## 데스크톱 반영

`npm run build`는 **203.033초**, `npm run smoke:desktop`은 **17.643초**에 통과했습니다. 패키지의 단일 창 재실행, 가격 조회 HTTP 200, 원가 계산 HTTP 200을 확인했습니다. 원문은 [Windows 빌드 로그](manufacturing-desktop-build-2026-09-07.log)와 [스모크 로그](manufacturing-desktop-smoke-2026-09-07.log)에 있습니다. 기존 Tailwind sourcemap/PyInstaller 경고는 성공한 빌드의 원문에 보존했습니다.

사용자 DB를 SQLite 온라인 백업으로 별도 보관한 뒤 기존 사용자 설치 경로의 COMET을 갱신했습니다. 설치 프로그램은 종료 코드 0이며, 설치된 `app.asar`와 백엔드 실행 파일의 SHA-256이 검증한 패키지와 일치합니다. DB 무결성 검사는 `ok`, 저장된 계산·재료·가격·장비 항목 수는 설치 전후 동일했습니다. 기존 바탕화면 바로가기는 올바른 경로여서 유지했습니다. 앱을 정상 모드로 다시 열었으며 **버전 1.4.0·건강 상태 ok·주 창 1개**와 설치 경로의 패키지 백엔드 실행을 확인했습니다. 메모리의 미저장 입력까지 백업했다고 주장하지 않습니다.

명령·소요 시간·소스 및 패키지 해시는 [검증 명세](manufacturing-checks-2026-09-07.json)에 기록했습니다. 준비 버전 1.4.0을 유지하며 같은 [PR112](https://github.com/hyunjin-kor/COMET/pull/112)에 반영합니다. 이 감사 기록까지 포함한 최종 head의 CI 결과는 PR 본문에 기록합니다. master 머지·태그·릴리스·외부 배포는 하지 않았습니다. 기존 자료 공백과 독립 실측 원가 검증의 한계는 이전 감사에 기록된 상태를 유지합니다.
